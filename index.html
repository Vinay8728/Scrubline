01 — LOAD

Read in memory

Your file is read straight into the browser tab via the File API. No network request is made with the image data.

02 — SCAN

Parse the real tags

A byte-level reader walks the file's own EXIF, GPS, XMP, and PNG text chunks to show you exactly what's embedded — not a guess.

03 — SCRUB

Re-encode clean

The image is redrawn onto a canvas and re-exported. Canvas export carries pixels only — every one of those chunks is left behind.

Quality lock: Resolution is never changed — width and height stay exactly as uploaded. PNG and WebP output is lossless. JPEG output is re-encoded at maximum quality (100%), so there is no visible or measurable quality loss and file size stays essentially the same as the original. The "reset pixel fingerprint" toggle is off by default precisely so pixels are left 100% untouched — only turn it on if you specifically want to defeat reverse-image/duplicate matching, since that option does nudge a small sample of pixel values by ±1–2 RGB.

What this can and can't do: Scrubline removes metadata that's stored as separate data inside the file — EXIF, GPS, XMP/IPTC, PNG text chunks, and markers used by tools like Automatic1111 or ComfyUI to store generation parameters. It cannot remove anything baked into the pixels themselves, such as an invisible watermark (e.g. SynthID), and it can't guarantee how any platform's classifier will read the resulting image. Treat it as a privacy and metadata tool, not a guarantee against AI detection.
